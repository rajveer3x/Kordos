# Kordos project context

Apply this workflow to every implementation request in this repository, including short requests such as “Start feature 01” or “Continue.”

1. At the start of an implementation session, read the six core files in order: [product overview](context/project-overview.md), [architecture](context/architecture-context.md), [UI context](context/ui-context.md), [code standards](context/code-standards.md), [workflow rules](context/ai-workflow-rules.md), and [progress tracker](context/progress-tracker.md).
2. Open the requested feature spec from the tracker. For “Continue,” resume the active feature if one exists. Otherwise select the first pending feature whose prerequisites are done. Check the tracker again when switching features.
3. Maintain the tracker as part of the work. Mark the feature Active when implementation begins. Before handing back, record the checks run, their results, any remaining work, and the next ready feature. Mark Done only after the acceptance checks pass. For a blocker, link the [issue log](context/current-issues.md) and record what is needed to resume.

The [final product specification](Team%20Workspace%20Final%20Product%20Specification.docx) defines v1 scope.
